<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| caller bytes → CHK core | Caller-owned plaintext, key, ciphertext, and address bytes enter security-sensitive code. |
| CHK core → public error/result | Internal authentication state and secret scratch data cross into consumer-visible objects. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Tampering | `decryptChk` | high | mitigate | Enforce ciphertext SHA-256 before GCM and plaintext SHA-256/CHK after GCM; test all bypass attempts. |
| T-02-02 | Information Disclosure | `encryptChk`/`decryptChk` errors | high | mitigate | One cause-free error shape plus recursive sentinel tests; never retain caller secrets. |
| T-02-03 | Tampering | per-chunk derivation | high | mitigate | Derive every invocation's key from its own exact plaintext and test distinct/identical/concurrent chunks. |
| T-02-04 | Denial of Service | byte inputs | low | accept | Operations are linear over caller-supplied in-memory bytes; bounded DAG streaming is Phase 4. |
| T-02-SC | Tampering | npm installs | high | mitigate | No install or upgrade occurs; use the audited existing `@noble/hashes` range only. |
</threat_model>
